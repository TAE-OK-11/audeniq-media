Round 11: FFmpeg-derived decoders restructured; every codec against FFmpeg 8.1.2
Host: 4 vCPU x86-64 container (Intel Xeon @ 2.10GHz). CPU = user+sys, median of 5-7
interleaved runs, single thread on both sides (ffmpeg -threads 1).

Decode. "ours" = audeniq-qc pcm-hash: full decode with all checks (frame CRCs, FLAC
MD5, WavPack sample CRC) plus SHA-256 of the canonical left-aligned s32le PCM.
"ffmpeg+sha256" = same output hashed (-c:a pcm_s32le -f hash -hash sha256);
"ffmpeg-decode-only" = decode to the null muxer (less work than ours).

TTA stages (album44, perf ms of samples): entropy 617 -> 370 (registers, branch-free
adaptation, word-refill reader), filter 392 -> 243 (C + x*Q form). An AVX2 filter
with the state in vector registers measured equal (cross-lane latency) and was not kept.
WavPack stages (album44): entropy (inlined, register state) 790 -> 650; a per-term
whole-block decorrelation measured slower (2.8 s vs 1.2 s on the high mode: one serial
chain per pass instead of overlapping terms) and was replaced by the per-sample order
with branch-free weight steps; check-free output when there are no extra bits.
FLAC 24-bit verification: an i64 constant-order path and an exact-f64 AVX2 path
(products and sums below 2^52 are exact) both measured equal to the existing code; not kept.

Equivalence: 5,400 CRC-repaired TTA mutations (stereo/mono, 16/24-bit) and 3,000 WavPack
mutations (payload, metadata, header) produce byte-identical stdout/stderr/exit status
to the round-10 binary (errors in the same order); all corpus outputs, qualify,
codec-stress, standards and mutation-fuzz counts unchanged; x86 and AArch64 (QEMU)
decode identically. New test: every TTA/WavPack mode (levels 0-3), mono/stereo,
16/24-bit, tone/noise decodes to the source PCM.
